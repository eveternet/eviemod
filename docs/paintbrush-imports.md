# Paintbrush helmet skins and PNG imports

## Scope and persistence

Explicit per-item selection or import is opt-in. There are no separate enable toggles. The legacy `helmetSkins` and `customTextures` settings are retained for config compatibility but no longer gate rendering or the editor. Model and PNG import share the Model tab. Only uploaded custom textures are excluded from armor in the UI, commands and runtime resolver. Standard model overrides, including matching gold-to-leather equipment and leather dye, remain supported. Helmet skins remain available separately.

Helmet skins are separate UUID-to-model mappings in `eviemod-helmet-skins.json`, using the existing validated atomic model store. They take precedence over regular model overrides only for player heads and equipment explicitly assigned to HEAD. Imports never change a server stack, its profile, equipment, stats or item behavior. Missing UUIDs and unavailable imported resources retain normal rendering. Malformed mapping files block writes until successfully reloaded.

Item PNGs become standard item definitions and models in `resourcepacks/eviemod-paintbrush`, under the reserved `eviemod_imported` namespace. Item sprites are stored under `textures/item/` to be discovered by the vanilla item atlas. Held-item model identifiers include their preset and SHA-256 of the normalized PNG plus canonical animation metadata, so later imports cannot replace another item's texture. Bow inherits `minecraft:item/bow` transforms; sword and generic handheld inherit `minecraft:item/handheld`. Only explicitly selected `.mcmeta` files are copied with the PNG after validation through Minecraft’s animation codec. No adjacent files are discovered or read. A non-square image whose larger dimension is a whole multiple of the smaller dimension prompts for metadata; this is a strip heuristic, not proof of animation. The player can choose metadata, use a static image, or cancel. Square/grid animations can supply PNG and metadata together. Frame dimensions must divide the image, indices must be in range, and timings must be positive. Empty explicit frame lists are rejected. Animation timing, ordering and interpolation are retained, but bow drawing stages are not generated. No remote upload or arbitrary model-file import occurs.

The desktop file chooser uses Minecraft's bundled LWJGL TinyFD. Dropping a PNG or its explicitly selected PNG/metadata pair into Model follows the same pipeline. Skin accepts catalog choices only; existing legacy imports continue to render and can be reset. Image validation happens off the render thread, checks PNG decoding, byte limits and dimensions before writes, and strips metadata. A 64 × 32 skin is padded to a 64 × 64 UV canvas; only the head and outer head layer are rendered. Individual generated files are replaced atomically, with the item definition last. For held items, a successful resource reload precedes changing the UUID mapping. Helmet skins instead register a DynamicTexture on the client thread and use the already baked vanilla player-head model. Persisted skins load asynchronously on first use, retaining normal appearance until ready. Failed imports preserve the previous mapping. Imported files remain available if the original source is moved or deleted.

## Minecraft 26.1.2 boundary

`TextureImportClient` isolates the native chooser, public resource-pack repository, options persistence and resource reload. The generated pack metadata targets format 84, matching the bundled Minecraft version. Pack selection is saved without calling `Options.updateResourcePacks`, because that method starts a reload without returning its future; the importer awaits exactly one explicit reload instead.

`ImportedTextures` writes the vanilla `minecraft:head` special renderer with kind `player` and the player-head item transform. In this version the special renderer prefixes its texture with `textures/entity/`, whereas the profile texture codec prefixes only `textures/`; the worn profile therefore uses `entity/` explicitly. Tests decode generated item definitions through Minecraft's real codecs.

`HelmetSkinRenderMixin` changes only `LivingEntityRenderer.extractRenderState`'s detached head state. It selects the normal player-skull renderer with a resource texture patch, without replacing a live PROFILE component. `HelmetSkinArmorMixin` skips only a helmet armor piece with an active, available skin, avoiding a second armor shell. Normal item rendering passes a detached stack copy with a resource PROFILE to the vanilla player-head renderer; live item components are untouched. These hooks and profile codecs must be rechecked on Minecraft upgrades.

## Catalog provenance and limits

The 119 base skins were extracted from [NotEnoughUpdates-REPO commit bf411c6e466e8fe36f117e8338349d17fd97c180](https://github.com/NotEnoughUpdates/NotEnoughUpdates-REPO/tree/bf411c6e466e8fe36f117e8338349d17fd97c180/items). Entries were selected from skull skin items whose lore explicitly describes application to a helmet, goggles, mask, head, crown or hat. Duplicate display names were disambiguated with the target from that same lore. The upstream MIT notice is included in `licenses/NotEnoughUpdates-REPO.txt`. The file contains names, item IDs and the Minecraft texture hash decoded from each item's texture property; it does not bundle downloaded skin images. This snapshot does not claim a complete or future-proof list.

The same snapshot’s [animatedskulls.json](https://github.com/NotEnoughUpdates/NotEnoughUpdates-REPO/blob/bf411c6e466e8fe36f117e8338349d17fd97c180/constants/animatedskulls.json) supplies 695 explicit variants. Each variant uses the first texture frame, with its label derived from the structured ID suffix. Animation frames are not misrepresented as separate selectable variants. Base selection exposes a separate searchable colour/variant field. New catalog assets use SHA-256 of `catalog:<stable skin or variant ID>` so selections sharing pixels retain distinct labels. Bundled `legacyHash` values match the previous importer’s normalized PNG hashes for the 119 base skins (ImageIO on Java 25, including legacy 64×32 padding), letting existing catalog choices display their names without network lookup. Unknown former custom imports display “Previously imported skin” and remain intact.

Autocomplete starts closed, stays closed on blank queries, and closes on acceptance, Escape, focus loss, and outside clicks (including blank panel space). The small screen input adapter handles blank-space dismissal because vanilla containers retain focus there.

Selecting a catalog skin downloads only its texture from `https://textures.minecraft.net/texture/<hash>`, with bounded size, timeouts, and no redirects. Imported user PNGs are never uploaded. Animated Hypixel skins use the static catalog preview texture; server animation timelines are not reproduced. Previously downloaded selections remain usable offline.

Local checks cover config validation, generated definitions, animation metadata validation and hashing, custom-texture armor exclusion and standard armor replacements, head texture paths, size limits, source-file deletion, and component immutability. Run `./gradlew runClient -PuiSmokeTest -PtextureCapture` for the development fixture. It exercises animated file-drop import, sprite stitching, merged Model UI, custom-texture armor exclusion and standard armor replacements, reload-free catalog downloads and variant selections, worn armor-stand rendering, per-UUID isolation, saved labels, persistence, reset and invalid-file recovery. Its screenshots are saved under `run/screenshots/paintbrush-*.png`. These checks are separate from live Hypixel and other-mod/resource-pack compatibility testing.
